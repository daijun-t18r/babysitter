# Repository Guidelines

## Project Structure & Module Organization

`backend/` is the FastAPI app (Python 3.12, managed with uv). Core code lives under `backend/app/`: `api/` (v1 routes), `ai/` (safety state machine, triage classifier, prompt builder, output filter), `core/` (config, auth), `db/`, and `services/`. Database schema is managed by Alembic in `backend/alembic/`; tests live in `backend/tests/`. `frontend/` is a Next.js App Router PWA (React 19, Tailwind 4, Supabase SSR) with source in `frontend/src/`. `supabase/` holds local-dev config for `supabase start`. `CONTRACTS.md` at the repo root is the authoritative frontend/backend contract — update it in the same PR as any API or schema change.

## Build, Test, and Development Commands

- `supabase start` brings up local Postgres + Auth + Studio.
- `cd backend && uv sync --all-extras --dev` installs backend dependencies.
- `cd backend && uv run alembic upgrade head` applies DB migrations.
- `cd backend && uv run uvicorn app.main:app --reload --port 8000` starts the API.
- `cd backend && uv run pytest` runs the offline backend suite.
- `cd backend && uv run ruff check .` lints the backend.
- `cd frontend && pnpm install && pnpm dev` starts the web app.
- `cd frontend && pnpm lint` and `pnpm build` are the frontend CI gates.

## Coding Style & Naming Conventions

Python uses 4-space indentation, Ruff with a 100-character line length, and snake_case modules. Keep business logic in `app/services/` and `app/ai/`, not in route handlers; database access is async SQLAlchemy. Frontend code is TypeScript with React 19: PascalCase components, `useX` hooks, Tailwind utility classes. The frontend must lint and build with zero env vars — env-gated features (e.g. the voice call UI) degrade gracefully rather than break the build.

## Testing Guidelines

Backend tests use pytest (`asyncio_mode=auto`) and live under `backend/tests/` as `test_*.py`, with HTTP mocked via respx. The suite is offline by default: live-API evals are marked `eval_live` and excluded; opt in with `uv run pytest -m eval_live`. Any change to API behavior, safety logic, services, or migrations ships with matching tests (including the Alembic tests). The frontend gate is `pnpm lint` + `pnpm build`.

## Safety Rules (product-critical)

This app advises exhausted parents of infants in the middle of the night, so safety behavior is non-negotiable. Red-flag triage, escalation copy, and the safety state machine live in `backend/app/ai/` — never weaken, bypass, or fork escalation paths, and emergency guidance must always surface to the user. Voice and text share one brain: the Vapi custom-LLM webhook routes through the app's own OpenAI-compatible endpoint so identical safety logic applies to both channels. Changes to medical guidance claims require clinical review before merging.

## Commit & Pull Request Guidelines

Use Conventional Commit prefixes (`feat:`, `fix:`, `docs:`, …) with concise, imperative subjects and one logical change per commit. PRs should include a short summary, test evidence (commands run and results), migration or env-var notes, and screenshots for visible UI changes. CI (backend ruff + pytest; frontend lint + build) must be green before merge. Alembic migrations are handwritten SQL via `op.execute` — RLS policies and triggers cannot be autogenerated — and every migration includes a working downgrade.
